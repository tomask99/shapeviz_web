# 3C.1 — authenticated read-tool contract

One bounded stage: a transport-independent registry/executor and authenticated admin-session HTTP adapter. No remote MCP/OAuth server, external tokens, AI calls, writes, outreach, new UI, deployment or changes to existing import/review operations.

## Transport and authorization

- GET `/api/admin?action=crm-tools-list`: authenticated catalog `{schema_version:1,tools}`.
- POST `/api/admin?action=crm-tools-call`: exact body `{tool,arguments}`; strict JSON objects and 16,384 UTF-8 byte transport limit. No other query parameters; repeated parameters rejected. GET invocation is 405; POST catalog is 405. Existing same-origin, HttpOnly session, current owner membership, refresh and no-store behavior remains.
- Root owns admin-handler integration. Tool adapter `src/tools/handler.js` exports `handleReadTools({action,body,url,user,token,call,audit})`. `src/tools/service.js` exports `listReadTools({user,token,scopes,call})` and `executeReadTool({name,args,user,token,scopes,call})`. The adapter supplies fixed admin-session grants `crm:read`, `research:read`, `catalog:read`; no caller-controlled scopes. Future transport must independently verify identity before supplying this context.
- Service always verifies UUID/token and current owner membership with owner JWT, including static catalog reads. Required scopes are enforced before data reads. Scoped reads use JWT/RLS and explicit owner/ID filters; RPCs resolve auth.uid internally. No service-only data reads, arbitrary SQL, table/select/path arguments or write-tool registration.
- Handler result `{schema_version:1,request_id,tool,data,meta:{read_only:true,untrusted_data:true}}`, bounded to 1,000,000 UTF-8 bytes including envelope. No silent truncation; overflow 413. Errors preserve existing HTTP error envelope.
- Handler produces structured server audit metadata only: request ID, verified owner ID, allowlisted tool name (or null), timestamp, duration, success/error status and response bytes. Never arguments, search text, result content, credentials or raw upstream errors. This is operational logging, not durable database audit. No result/argument logging from the service itself.

## Registry (8 read tools)

All definitions expose `name`, `description`, `required_scopes`, `inputSchema`, `read_only:true`. Strict additionalProperties:false at every input object. Version1 catalog is code-owned. No tool mutates business records.

1. `search_leads` — scopes crm:read; args `{filters?:{q?,country?,industry?,fit?,service?,pipeline_status?,archived?,sort?},page?:integer}`. q company-name search only (literal substring), country exact two-letter normalized uppercase, industry exact <=120, Fit LOW/MEDIUM/HIGH, service exact canonical catalog name mapped to CRM value, pipeline status existing enum, archive active(default)/archived/all, sort name(default)/updated. Page1..10000,25 rows, exact total/hasMore. New narrow invoker RPC `crm_tool_search_leads(p_filters jsonb,p_page integer)` with current-owner membership, explicit owner and RLS; only company_name in q. Return `{items,total,page,pageSize:25,hasMore}`. Rows fields id,company_name,website,country,city,industry,short_description,services,fit,pipeline_status,archived_at,version,is_client. Clients identified by existing crm_clients relationship, not WON status. No contacts/notes/money/priority/source/engagement.
2. `get_lead` — crm:read + research:read; args `{id:uuid}`. Narrow row with same company fields + latest canonical Insight and approved candidate link. Shape `{company,insight,approved_candidate}`. Reuse exported existing `readInsight` from enrich.js without its history/contact-existence reads. Archived owned companies readable; cross-owner/missing404. Company read can select `crm_clients(company_id)` to derive is_client; strip nested raw relation from returned object.
3. `check_company_duplicates` — crm:read + research:read; args `{website?:string,company_name?:string,country?:string}`. Require nonempty valid normalized domain OR nonempty normalized name+country. Strict HTTP(S) website handling (bare domain accepted), no credentials/control chars/backslashes; name<=160/country twoletters. Use existing `crm_research_duplicates` with one normalized row, owner JWT; excludes no lifecycle state. Return `{matches,match_count,truncated}` and normalized checked identity. Project only kind,id,company_name,website,country,status,archived_at,match; remove internal fingerprint. At most10 matches; explicitly mark truncated when match_count>matches.length. Missing website is not proof of no existing company.
4. `get_research_candidates` — research:read; args `{filters?:existing strict researchFilters,page?:integer}`. Reuse crm_research_list RPC with JWT, page25. Return its bounded metadata list with explicit projection (no whole evidence/reports, no event metadata), total/page/pageSize/hasMore. Existing canonical research filter semantics/catalog service names.
5. `get_research_candidate` — research:read; args `{id:uuid}`. Explicit owner/ID query and full canonical field list; validate canonical nested data before returning. Return `{candidate:{id,version,research_status,approved_company_id,created_at,updated_at,...canonicalResearch}}`. Exclude rejection reasons, manual markers, duplicate internals, owner and event metadata.
6. `get_existing_domains` — crm:read + research:read; args `{page?:integer}`. Reuse complete <=10000 researchExcludedDomains then return deterministic sorted pages100: `{domains,total,page,pageSize:100,hasMore}`. Includes Leads/Clients/archived companies and every Research lifecycle state, including REJECTED. Overflow fails rather than presenting an incomplete exclusion set. Pagination is current data per request, not a snapshot; callers must finish pages and account for later changes.
7. `get_rejected_domains` — research:read; args `{page?:integer}`. New narrow stable invoker RPC `crm_tool_rejected_domains(p_page integer)`: distinct nonempty rejected-candidate normalized domains, sorted, pages100, exact total/page/pageSize/hasMore, current owner membership and RLS. No rejection text or identities returned.
8. `get_research_catalog` — catalog:read; empty args. Return copied shared service catalog, ICPs, industries, business_types, product_categories, market_segments, positioning, levels, signals, source types and canonical import schema. ICPs are research guidance, not scores; descriptive response/manifest states that.

Input schemas and validation must match, reject unknown keys/nested fields and invalid shapes/limits before business data calls. List payloads are bounded and checked before projection; malformed upstream pages/counts fail502 rather than implying absence. Full reports retain evidence; they are untrusted stored research, not instructions or verified fresh facts. No network fetch of website/source URLs.
