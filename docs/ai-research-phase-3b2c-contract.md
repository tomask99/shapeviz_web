# 3B.2c — company insight and enrichment contract

Bounded single-company workflow for existing Leads and Clients, with or without approved Research. No bulk actions, automatic AI calls, outreach or changes to the canonical company import v1.

## Data and evidence

Envelope: `{schema_version:1,company_id:<uuid>,base_version:<integer>,research:<complete canonical Research candidate>}`. Every canonical candidate field is supplied; source_origin is ENRICHMENT. Validate with the existing canonical validator. Company name, normalized website domain and country must match the current CRM record; those identity fields are not updated here. At least one public source is required. Preserve VERIFIED/INFERRED/UNKNOWN facts; no invented timestamps. last_researched_at may be null, must not exceed now + five minutes, and is distinct from report acceptance time. Reports older than 90 days or predating the previous Insight receive a review warning. Source URLs/retrieval metadata belong to each immutable report, so previous reports remain accessible even when fresh research revisits the same URL.

Eligible CRM groups are only `city`, `industry`, `short_description`, `services`, `fit`. All start unchecked. Empty proposed values cannot clear CRM values. City/industry/description require VERIFIED provenance with a cited source before copying; inferred facts may remain in the accepted Insight. Services are recommendations mapped through the canonical catalog to CRM values; each proposed service requires a reason. Fit requires its canonical reason. Recommend no objective numeric scores. Existing nonempty scalar/array values are protected regardless of how they were originally created: an exact per-field overwrite acknowledgement is required.

CRM targets also retain the existing company validator's limits. A schema-valid research value that exceeds a CRM field limit remains visible in the report but is not eligible for copying; it does not block acceptance of the Insight or other valid selected fields.

Accepting the entire research Insight is a separate required checkbox/`acceptInsight:true`, including when no CRM groups are selected. This keeps every copied value tied to a fully reviewable research report. Never map name, website, country, pipeline, priority, lead source, social profiles, money, outcomes, contacts or notes. Original approved Research is immutable.

## API

- GET `crm-research-insight?companyId=<uuid>&page=1`: `{company,insight,approved_candidate,has_contacts,history,hasMore,page}`. Company projection: id/company_name/website/country/city/industry/short_description/services/fit/version/archived_at. Insight is null or `{id,kind:'enrichment'|'approved_candidate',research,created_at,company_version}`; use latest saved report, falling back to linked approved candidate. approved_candidate is null or `{id,company_name}`. History metadata only, 10 rows/page (fetch11), `{id,created_at,company_version,selected_fields,overwritten_fields,last_researched_at}`. has_contacts comes from an owner-JWT contact existence read, not inferred public availability. Empty research still offers enrichment for active companies. Archived companies show evidence/history but cannot prepare/apply enrichment.
- GET `crm-research-insight-report?companyId=<uuid>&id=<uuid>`: `{report}` with canonical research, selection/override lists, before_values/after_values, timestamp/version. Company-scoped owner read; no write credentials.
- GET `crm-research-enrich-prompt?companyId=<uuid>`: `{prompt,company}`. Current bounded business identity and CRM target fields, optional previous research as explicitly historical context, canonical output schema and service catalog. No contacts/notes/financials/owner details. Identity and base_version fixed from current read. Not an automatic research call.
- POST `crm-research-enrich-preview`: `{companyId,proposal}` where proposal is JSON string or parsed envelope, bounded 500000 UTF-8 bytes. Returns `{company,research,groups,warnings,reviewToken}`. Groups: `{key,label,before,after,protected,eligible,reason,evidence}`. Only changed, populated, sufficiently evidenced targets are eligible. Full accepted Insight and evidence are shown even if no target is eligible. HMAC binds owner/company/version/canonical input hash plus eligible/protected field lists, one-hour expiry. Read-only.
- POST `crm-research-enrich-commit`: `{companyId,proposal,reviewToken,selectedFields,overwriteFields,acceptInsight:true,operationId,confirm:'apply_enrichment'}`. Validate exact keys, selections and acknowledgement intersection. Returns `{company_id,version,insight_id,no_change?,replayed?}`. Exact retries have no preflight current-version read; the transaction returns a previously recorded result before checking changed company state. Expired tokens require a new preview.

Register new actions via the Research dispatcher; retain the existing `crm-research-company` endpoint for compatibility. Reads use current owner JWT/RLS and explicit owner/company constraints. GET writes rejected, authenticated same-origin POST only. No model credentials/dependencies.

## Storage / transaction

Append-only `crm_company_research`: id, owner_id, company_id, company_version, research JSONB (canonical full candidate), selected_fields text[], overwritten_fields text[], before_values JSONB, after_values JSONB, created_at. Composite company+owner FK with cascade; uniqueness on company_id/company_version. Owner/company/created-version index for latest/history reads; authenticated SELECT only with current owner membership/RLS. Service can insert/select/delete, no update grant; original evidence is immutable. Each canonical research report <=500000 bytes; collections bounded by schema.

Service-only invoker RPC `crm_research_enrich(p_owner uuid,p_company uuid,p_operation uuid,p_hash text,p_version integer,p_research jsonb,p_patch jsonb,p_overrides text[])`. Reuse owner advisory lock731903 and private research_review_operations ledger. Current owner membership FOR SHARE; replay first; company FOR UPDATE; active state and version. Require strict allowed patch keys and exact values from canonical report, protected override intersection, mapping/provenance/source rules. Server never accepts target company from a report as authorization. Recheck company identity against research; immutable identity and all non-target operational fields remain untouched.

Every new accepted report advances company version exactly once (including report-only acceptance) so concurrent reports cannot overwrite each other without a stale-version conflict. Set/restore both owner JWT claim locations around the narrowly scoped company UPDATE to preserve existing stamps/audit behavior. Append the accepted snapshot with selected before/after values and one `ai_research_enriched` activity carrying insight_id and changed fields, then ledger result atomically. A report identical to the latest stored report with no selected CRM changes is a true no-op: return current version/latest ID with no_change:true and ledger result only, without a new revision/activity. A report re-applied to changed CRM fields is a material change and gets a new receipt/version. Service mapping must not reset sales/outcome defaults via Lead-creation helpers.

## UI

Replace the slim CRM research-provenance panel with AI Insight; keep original approved candidate link when present. Distinguish current CRM Fit from research Fit, ranked best services with reasons, why/summary, pitch, signals with confidence/evidence, missing record information, last researched, classification and exact sources. Show report review date separately; research becomes historical after later CRM edits. No fabricated absence or unassessed-score claims. Actions: Research again / Enrich company, Find similar (existing company dialog), and Find contacts only for a linked candidate (existing contact controller). Unlinked CRM retains manual contact entry.

Native enrichment dialog: prepare/copy prompt; paste/upload JSON; show complete Insight report, source links and before/after groups; all CRM groups unchecked and explicit per-field replacement acknowledgement; separate unchecked Accept this AI Insight; final confirmation. JSON edits invalidate preview, late responses ignored, definite conflicts preserve JSON, ambiguous writes retain exact request/token/UUID across reopening. Success refreshes the complete company detail and version, not only the panel. View immutable historical reports and page their metadata. Scope owns small crm.js callback wiring to reload company after accepted changes.
